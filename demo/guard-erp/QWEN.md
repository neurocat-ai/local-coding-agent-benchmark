# Repository instructions

- Read `TASK.md` before changing code.
- Work only inside the repository copy you were given. Do not create another copy and do not edit `TASK.md`.
- Keep the public API stable unless the task requires a contract change.
- Prefer a focused change over broad refactoring.
- Add tests for new behavior.
- Run `dotnet test GuardErp.sln` before reporting completion.
- Do not add production credentials, external services, or customer data.
- Finish with a concise summary of the changed files and test result.
